# Staging migration identity (source contract only)

`infra/foundation/staging-migration-irsa.tf` defaults `staging_migration_irsa` to null: no role or policy is created. Enabling it requires the explicit role name `oficina-phase3-staging-migration`, APP source commit, exact bootstrap-review SHA256, and five reviewed secret references. The existing `oficina-app` role and production overlays remain unchanged.

Each `secret_refs` entry (`master`, `migration`, `app`, `auth`, `notification`) requires an exact same-account staging Secrets Manager ARN, immutable `version_id`, `metadata_sha256`, and `kms_key_manager` (`AWS` or `CUSTOMER`). CUSTOMER requires the exact KMS key ARN; AWS requires no customer key grant. Obtain these from reviewed Terraform outputs/nonsecret secret/key metadata, never infer ownership or fabricate an ARN. The metadata hash identifies the separately retained review receipt; source validation does not prove that receipt describes live AWS.

Trust binds only the foundation OIDC provider, `sts.amazonaws.com` audience, and `system:serviceaccount:oficina-staging:oficina-migration-staging`. The inline policy allows only `GetSecretValue` and `DescribeSecret` on those five ARNs, restricted to `us-east-1`. `DescribeSecret` supports metadata/version validation without granting secret mutation. AWS-managed keys add no explicit `kms:Decrypt` statement. CUSTOMER keys receive only `kms:Decrypt`, restricted by caller account, Secrets Manager ViaService, and exact SecretARN encryption context. Secret version selection is enforced by the APP bootstrap SDK's exact VersionId request; IAM grants read access at secret resource level. There are no Secret writes, SQS grants, production resources, or access-policy associations.

1. Review the optional Terraform input and plan independently. This change performs no apply. Export `staging_migration_identity_json` with `terraform output -raw` into UTF-8 **without adding a newline**; preserve those exact bytes and `staging_migration_identity_sha256`.
2. Render locally with `scripts/render-staging-migration.ps1 -Enabled -IdentityFile <identity.json> -ExpectedIdentitySha256 <hash> -BootstrapReviewFile <bootstrap-review.json> -DatabaseCidrs <reviewed-db-cidrs> -AwsHttpsCidrs <reviewed-https-cidrs> -OutputDirectory <empty-output>`. Omission of `-Enabled`, production, unresolved CIDRs, or mismatched identity/review bytes fails. No cluster/cloud commands are executed.
3. Review the two output objects independently: `migration-serviceaccount.json` and `migration-network-policy.json`. DNS peer/ports follow `k8s/platform/base/network-policies.yaml`; DB TCP5432 and AWS HTTPS TCP443 CIDRs are explicit inputs with no defaults. Include all DB failover subnets. HTTPS routes/endpoints must reach STS and Secrets Manager; `0.0.0.0/0` would require an explicit reviewed input, never an inferred default. The policy selects only APP's `oficina-migration` Job label.
4. Put the exact identity string into APP platform JSON `MigrationIdentityJson`, its SHA256 into `MigrationIdentitySha256`, and renderer receipt `networkPolicySha256` into `MigrationNetworkPolicySha256`. The APP release's `platformInputsSha256`, existing immutable platform object key/VersionId, and manifest hash bind this envelope. Preserve `bootstrapReview` serialization when packaging: its hash must equal the identity's `bootstrapReviewSha256`.
5. Later staging plan/apply must pin source/template/identity/network hashes, verify source-derived namespace/RBAC/controller prerequisites, and capture SA role annotation plus UID/resourceVersion and NetworkPolicy readback. APP reads the SA twice under its shared lock before migration; it does not create identity resources. Staging RBAC adds only that exact SA name to the existing GET rule. Existing SA CREATE capability is unchanged.

The SA has `automountServiceAccountToken=false`; the EKS IRSA admission webhook must inject its separate projected `sts.amazonaws.com` token into the migration Job. Webhook injection, AWS SDK credential use, TLS/DB access, network enforcement, and secret metadata/KMS correctness still require live evidence. The Terraform output and renderer receipt are **not runtime success receipts**. No production activation is supplied.

Focused checks: `tests/staging-migration-tests.ps1`, `tests/staging-app-workload-tests.ps1`, mocked `infra/modules/staging-migration-irsa/tests/identity.tftest.hcl`, and foundation default-disabled output assertions. All fixture ARNs are synthetic. Known runtime ConfigMap/SPC/Service/base NetworkPolicies and TargetGroupBinding transport remain separate prerequisites.
