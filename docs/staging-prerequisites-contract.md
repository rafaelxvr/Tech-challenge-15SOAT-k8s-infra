# Staging prerequisite bundle and private executor

This contract installs platform-owned objects before APP FirstWriter. It does not grant APP NetworkPolicy or TargetGroupBinding permissions. Existing runtime IRSA, production manifests, standard foundation buildspec, and APP's six/seven-artifact receipt fields are unchanged. No cloud operation was performed while implementing this contract.

`scripts/render-staging-prerequisites.ps1` selects the Service, two NetworkPolicies and SecretProviderClass from the hash-pinned `render-platform.ps1` output. It adds the hash-pinned migration renderer ServiceAccount/egress policy and public ConfigMap, and invokes the existing target-binding renderer with `infra/environments/staging` Terraform output `target_group_arn`. The result contains exactly eight namespaced objects; no Secret, Namespace, Role, Deployment, HPA, or production object can enter this bundle.

1. Supply explicit reviewed files and hashes: platform YAML, public ConfigMap JSON, migration directory/receipt, APP/K8S source commits, and `terraform output -json` from staging. Supply its immutable artifact bucket, key `releases/k8s/staging/outputs/<k8sCommit>.json`, VersionId and SHA256. Output JSON must contain staging `environment`, `namespace` and exact `target_group_arn`. ARNs/CIDRs/key versions are never discovered or guessed by the renderer. Existing renderers own secret-reference, migration IRSA and network inputs.
2. Review `staging-prerequisites.json` and its render receipt. The bundle carries exact Terraform output bytes/hash/version identity. Publish reviewed inputs separately: source archive at `foundation-addons/bundle.zip`; bundle/window at `foundation-addons/manifests/staging/<appCommit>/prerequisites.json` and `cloud-window.json`. The source archive must contain the selected K8S commit's scripts, unlike the existing addons-only archive. Bind its hash and immutable VersionId independently.
3. `prepare-staging-prerequisites-execution.ps1` requires `-Enabled true -CreateReviewedObjects` plus all immutable source/bundle/window inputs. It emits a review-only StartBuild payload for **only** `oficina-phase3-foundation-addons`, never calls AWS, and does not update the project. The bounded buildspec override downloads exact versions, verifies returned VersionIds/hashes, prepares private kubeconfig and invokes `install-staging-prerequisites.ps1`; it never runs the standard addons Terraform plan/apply. Review project/source/deployer/account/access policy equality, no-active-build state, source archive contents and an unexpired staging cloud window again immediately before any separately authorized dispatch.
4. The installer defaults to local validation. Actual execution requires its explicit creation flag and the existing foundation CodeBuild project/assumed-role identity. It acquires `deployment-locks/shared-foundation.json`; the foundation IAM delta grants only GET/PUT/DELETE for this existing shared-lock object. Existing S3 read permissions already cover the `foundation-addons/manifests/*` inputs. An Active namespace is required. All eight objects must be absent, or all must match. Partial state/drift stops. Fresh creation requires no namespace pods, server-side dry-run of every object, another absence check, then Kubernetes CREATE (never apply/patch). Immediately before each persistent CREATE, source/archive/bundle/window/object-byte hashes and current staging window time are checked again. Expiry or replacement stops all remaining Kubernetes writes. AlreadyExists stops without overwrite. Matching-existing runs are read-only and produce a new receipt.
5. Review/publish the complete private readback as `foundation-addons/manifests/staging/<appCommit>/readback.json`. Put exact bundle JSON/hash and receipt JSON/hash/bucket/key/VersionId into APP's existing platform JSON fields documented in the companion APP contract. Re-publish the existing immutable platform artifact and manifest hashes. Historical six/seven-input receipt fields retain their meanings; a new execution requires these additional platform fields and a reviewed foundation receipt.

The readback records exact UID/resourceVersion and source-controlled metadata/spec/data for all eight objects. Service API-assigned ClusterIP/family fields and defaults are excluded from desired-spec comparison. The full public ConfigMap contains public verification keys and public CA only; no Secret GET/list or secret values are collected. `create-responses.json` captures each CREATE response UID/resourceVersion before semantic validation or GET and is explicitly unverified creation evidence. A following GET must match that CREATE UID before entering `created-objects.json`; failed/replaced readbacks never authorize rollback. Both files reset for each execution, and the success receipt stays EXECUTION_PENDING on interruption. `created-objects.json` retains only matched partial ownership evidence after a failure. No automatic rollback is provided: a separately reviewed recovery must compare current UID/resourceVersion before deleting only objects created by that run. Partial creation deliberately blocks subsequent automatic execution. Admission/controllers/CRDs must be installed; failed server dry-run stops before persistent creation, including any webhook that cannot validate prerequisites while absent.

APP validates this immutable foundation receipt for TGB/NetworkPolicy evidence, then live-reads only its permitted Service, SecretProviderClass, migration SA and public ConfigMap. It cannot independently detect later TGB/NetworkPolicy drift. Require a fresh reviewed foundation readback immediately before the APP window; hashes prove provenance, not continuing live correctness. Runtime routes, targets, CSI synchronization, IRSA token injection, migration and rollout remain pending cloud evidence.

TargetGroupBinding readback tolerates only two controller-populated fields when they are absent from the reviewed desired spec: `ipAddressType` must be the scalar string `ipv4`, and `vpcID` must be a scalar AWS VPC identifier (`vpc-` plus 8 or 17 lowercase hexadecimal characters). Comparison removes these fields from a copy, retaining the complete CREATE response and GET metadata for ownership evidence. Any explicitly desired value remains strictly compared. Target-group ARN, target type, service name/port, metadata and every other field remain strict; unknown additions and malformed defaults fail closed. This normalization recognizes provider-owned output; it does not independently establish VPC ownership. Pin `spec.vpcID` in a reviewed desired object when exact VPC comparison is required.

The failure that motivated this change created all eight staging prerequisites before the original validator rejected the final TargetGroupBinding's added fields. A later read-only diagnostic found seven exact objects and only these two additions on the TargetGroupBinding. This source fix does not change the historical failed build to success or authorize retry, deletion, rollout or production. Obtain a separately reviewed read-only receipt against the corrected contract before continuing activation.

APP has a copied `scripts/staging-prerequisites-contract.ps1`, loaded by `scripts/app-prerequisites-contract.ps1`; it does not import this file from K8S at runtime. Apply the identical normalization to that APP copy in the coordinated release and test receipt acceptance there. Updating only K8S leaves APP rejecting the complete foundation receipt. No bundle schema or field hash changes are needed for this comparison-only fix.

Offline checks: `tests/staging-prerequisites-tests.ps1` uses real source renderers and mocked executor boundaries; foundation executor mocked Terraform tests assert the exact shared-lock policy; existing platform/workload contracts remain in CI. The shared `staging-prerequisites-contract.ps1` is copied identically into APP for artifact/readback validation; review both repository hashes when changing its schema.
